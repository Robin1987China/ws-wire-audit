Five-Venue WebSocket Market-Data Comparison — Same Caliber

Wire-level traffic of five public crypto-spot trade feeds over one WebSocket connection, measured with the same tool, window and caliber.

五种现货行情 WebSocket 推送的同口径对照页 · 页面上的每个数字都可回源到仓内 examples/ 的场次 JSON。

This is a single self-contained page: one clickable link a post or article can cite, instead of a repository. It reports what a feed actually put on the wire — message rate, byte rate, message size, compression state, subscription acks, control frames and heartbeats — for LBank, Binance, Bybit, OKX and Kraken, under one declared caliber.

It is not a venue ranking. Most rows are single observations; two venues reach n=3. Read the Limits section before quoting any number. Numbers here are observations under a declared caliber, not properties of a venue.

Caliber — the four declarations (summary of SPEC)

Per the repository's SPEC, two numbers are comparable only if these four quantities are declared:

  1. Business-message definition — one inbound data frame, excluding RFC 6455 control frames, application heartbeats and subscribe acks; inbound only; fragments not reassembled.
  2. Payload vs. wire bytes — payload = inbound bytes after decompression; wire = on-wire WebSocket frame bytes as read (header included, compressed bytes if the frame arrived compressed). Both exclude TLS/TCP/IP overhead; client→server is not measured.
  3. Compression-negotiation state — four states, never a boolean: not_offered / server_refused / accepted / unsolicited.
  4. Egress and observation window — calendar time, window length and start point (after subscribe), sessions run, reconnects, and egress region/ASN.

Full text: SPEC.md. Caliber used for every row on this page: business message = non-heartbeat inbound data frame; bytes = wire (as-read) and payload (post-inflate), one direction; compression state per venue (below); window = 600 s starting after subscribe; one connection per venue, no reconnect, no concurrency, one egress (AS4812, China Telecom) observed 2026-09-22 and 2026-09-29/30 GMT+8.

4. Limits — read before citing any number

  • Single vs. multiple observations. LBank, Binance and OKX are each n=1 — one session is an observation, not a distribution. Only Bybit and Kraken reach n=3.
  • A venue's own cross-session variation is as large as some between-venue gaps. Bybit's wire-rate spread is +80.8% and Kraken's +116.3% across their three sessions — each is at least as large as the gap between several venues. A single-session byte-rate ordering whose gap is smaller than the venue's own spread cannot be attributed to the venue: Bybit's n=3 range [5,619.8, 10,159.5] straddles OKX's 6,568.7, so the n=1 claim "Bybit > OKX by wire B/s" does not hold.
  • Rate-type quantities are not decidable at narrow gaps. A same-window interleaved A/B (Bybit vs. OKX alternating, 6 rounds × 60 s) found the byte-rate ordering not decidable: the paired A−B sign flips once within the window. Message-rate direction and per-message size were decidable in that run; byte rate was not. Treat all byte-rate orderings with < ~1.8× separation as undecided at n=1.
  • Kraken is not a suitable throughput sample. In all three sessions, business frames (96–235) are fewer than the venue's heartbeat frames (622–623, ≈1 frame/s). At 39–85 B/s the absolute volume is minuscule, so its +116% spread is a relative figure on a tiny base and must not be read alongside Bybit/Binance spreads. Its USDT books are thin because most of its assets quote in USD, which was not measured here.
  • Structural quantities are stable; rate quantities are not. Subscribe acks (LBank 0, Binance 1, Bybit 11, OKX 110, Kraken 20), control frames (only Binance 30) and the compression states were constant across sessions — they are not affected by the rate spread.
  • Different symbol sets. Each venue was measured on its intersection with a 159-asset watchlist (Bybit 103, OKX 110, Kraken 20), not on a common symbol set.
  • One egress. All sessions ran from a single egress (AS4812). A different region may change these results; re-measure before generalising.

5. Reproduce

One command reproduces a session of this shape (the tool and watchlist are in the repository):

python3 measure_ws.py --venue bybit --symbols-file <symbols-file> --duration 600 --out <workdir>/bybit-600s.json

<symbols-file> is the 159-asset watchlist restricted to the venue's listed pairs (see the per-venue counts in Table 1); <workdir> is any output directory. The tool uses the standard library only and contacts public, unauthenticated endpoints.

Repository: github.com/Robin1987China/ws-wire-audit  ·  Rule: SPEC.md

SPEC four declarations, in one line: declare (1) what counts as a business message, (2) whether byte counts are payload or wire, (3) the compression-negotiation state (four states, not a boolean), and (4) the egress and observation window — before comparing any two feeds. Two numbers produced under undeclared or differing choices of these four are not a comparison, even when both are correct.
